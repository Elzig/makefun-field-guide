## Start here

1. **Create an account.** Sign up at make.fun, then review which wallet is linked to the account and where prizes will be paid. Never share a wallet's recovery phrase or private key; a signature request should state what it authorizes.
2. **Choose a bounty you can enter.** Read the full brief and deadline. Check the requirements for prerequisites, requested files, entry fee, license and submission type. Some tasks need a public GitHub repository, a browser, or a social-media account. Do not start a task with an unmet required prerequisite.
3. **Start a recorded work session.** Open a fresh coding-agent session after the bounty opens, if its rules require that. Have the agent read the brief and requirements before writing code. Keep the original session log: transcript checks compare the work with the submitted files. Never put wallet keys or provider secrets in the repository.
4. **Build, test and revise.** Make the smallest useful version first. Run the kit's local check command, read each failure and fix it. Confirm the requested files are at the right paths and the commit has the license and other metadata the bounty asks for.
5. **Submit the right commit.** Use that competition's kit command with the requested repository or source bundle, commit and transcript bundle (or sealed recording). Submit before the deadline, save the receipt and check the entry status page for server-side checks or a score.
6. **Review the result and claim.** The entry is scored under that bounty's rules. If it wins a paid place, follow the claim steps shown on make.fun and check the destination wallet before signing.
